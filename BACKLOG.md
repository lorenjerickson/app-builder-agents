- **P4 — Give Requirements an explicit actor-profile (persona) output.** Source: rental-ops RUN-20261025-CR01 clean-room comparison (rental-ops/delivery/runs/RUN-20261025-CR01/comparison.md), 2026-10-25. Both runs invented a persona format, and the original put UI prescriptions in it. Findings U3, U16. Owner: Loren. Status: proposed.

- **P17 — Separate configurable service targets from system quality thresholds in requirements_spec.** Source: rental-ops DR-08 partial decision, 2026-10-25. `quality_thresholds` assumes fixed system targets (metric, target, workload). The authority decided that response times are tenant-configurable business policy, with shipped defaults per property, request type and calendar, while uptime and recovery stay system thresholds. Proposed delta: add `configurable_targets` (dimension keys, default values tagged as proposals, override rules, precedence against legal deadlines) separate from fixed `quality_thresholds`, with matching Testing guidance (verify configurability and defaults rather than one number). Owner: Loren. Status: proposed.
- **P18 — Add a threshold-consistency check to Requirements.** Source: rental-ops DR-08 completion, 2026-10-25. The authority set a 99.9% minimum availability and a 2 h total-outage RTO; under a monthly window (≈ 43.8 min allowance) a single compliant recovery would breach availability. Only choosing a measurement window (quarter or longer) makes them consistent. Proposed delta: Requirements step 8 checks thresholds against one another (availability vs RTO vs degraded-mode limits vs maintenance windows), requires a measurement window for every percentage target, and requires an "essential functions" definition when degraded operation is allowed. Evidence update: the authority intended an annual window. Requirements should *ask* for the window and present the arithmetic (monthly / quarterly / annual allowances), not propose one. Its essential-functions proposal was also over-inclusive for a low-frequency domain; elicit criticality from the authority, using the domain's urgency profile. Owner: Loren. Status: proposed.
